# TIME — игровое время и длительности (этап X0)

Документ описывает модель времени движка: как считается игровое время, как
эффекты (состояния и баффы) истекают «по часам», и как время переживает границы
отдельных боёв. Это фундамент исследования мира (этап X) и закрытие долга T2
(`OngoingEffectTracker` раньше снимал эффекты только по событиям, без срока).

## 1. Канон — раунд

Единица игрового времени — **раунд** (PHB-2024 стр. 20: раунд ≈ 6 секунд).
Все длительности приводятся к раундам в одном месте:

| Единица | Раундов |
|---------|---------|
| 1 раунд | 1 |
| 1 минута | 10 |
| 1 час | 600 |

Потребители времени (часы, трекер эффектов) работают **только с раундами** —
минуты/часы конвертируются на входе.

## 2. `Duration` — длительность эффекта

`dnd.domain.values.duration.Duration` — иммутабельный value-объект
(`unit: DurationUnit`, `amount: int`). Конструкторы-удобства: `Duration.instant()`,
`.rounds(n)`, `.minutes(n)`, `.hours(n)`, `.concentration(cap_min=0)`.

`to_rounds() -> int | None` — длительность в раундах; `None` означает **нет
счётного предела**:

- `INSTANT` → `0` (мгновенный эффект, по часам не снимается);
- `ROUNDS / MINUTES / HOURS` → конечное число раундов (`amount > 0` обязателен);
- `CONCENTRATION` → потолок в раундах при `cap_min > 0`, иначе `None`
  (длится, пока держится концентрация);
- `PERMANENT / UNTIL_ENCOUNTER_END` → `None`.

## 3. `GameClock` — монотонные часы

`dnd.domain.entities.game_clock.GameClock` — счётчик игрового времени в раундах,
старт `0`, только вперёд:

- `advance(rounds)` / `advance_minutes(n)` / `advance_hours(n)`;
- `expires_at(duration) -> int | None` — раунд, на котором эффект истечёт
  (`now_round + duration`); `None` для длительностей без счётного предела.

Часы **двигает только `Encounter`** — на границе раунда, **до** публикации
`RoundEnded` (см. `_advance_turn_pointer`), чтобы трекер сравнивал дедлайны с уже
обновлёнными часами. Все остальные (трекер, UI) часы только **читают** — двойного
продвижения нет. В исследовании (этап X) часы будет двигать переход локаций /
обыск / отдых по стоимости действия.

## 4. Истечение эффектов по часам

Длительность **дополняет** существующие триггеры снятия (урон / повторный
спасбросок / срыв концентрации), а не заменяет их. Источник эффекта вычисляет
дедлайн через `GameClock.expires_at` и кладёт его в событие; `OngoingEffectTracker`
(clock-aware) на каждом `RoundEnded` снимает то, чей дедлайн достигнут.

**Состояния.** `ConditionApplied.expires_at_round: int | None`. Хендлер
(`ControlSpellHandler`) ставит дедлайн только для **конечной положительной**
длительности; для `INSTANT` / безлимитной → `None` (Sleep снимается уроном, а не
по часам). Снятие по часам публикует `ConditionRemoved(reason="duration")`.

**Баффы-модификаторы.** `BuffApplied(owner_id, source_id, expires_at_round)` /
`BuffExpired(owner_id, source_id)`. После добавления модификатора в
`ModifierApplier` хендлер (`BuffSpellHandler`) публикует `BuffApplied` — но только
для конечной длительности (бафф концентрации без потолка снимается срывом
концентрации, как раньше). По достижении дедлайна трекер вызывает
`remove_by_source` и публикует `BuffExpired`.

Правило «только конечная положительная длительность» инкапсулировано в хелпере
`handlers._expires_at`: `INSTANT (0)` и безлимит (`None`) → дедлайн не ставится.

## 5. `GameSession` — время поверх боёв

`dnd.application.engine.game_session.GameSession` держит партию + общие часы +
сервисы. Бой создаётся из сессии и делит её часы:
`EncounterRuntimeServices.clock` → `with_battlefield` → `EncounterDependencies.clock`
→ `Encounter`. Тот же объект часов получает `OngoingEffectTracker`, поэтому эффекты
истекают по тем часам, что двигает бой. По `EncounterEnded` управление возвращается
в сессию — часы и активные эффекты сохраняются (временны́е баффы корректно истекают
через границу боёв).

Режим исследования (локации, диалоги, квесты) — этап X; сейчас `GameSession`
оборачивает бой и фиксирует единство времени и длительностей.

## 6. Контент

Длительность задаётся данными у заклинания (`data/content/spells.yaml`,
поле `duration: { unit, amount }`; отсутствие → `INSTANT`). По PHB-2024:

| Заклинание | duration |
|------------|----------|
| Bless | `concentration`, 1 мин (10 раундов) |
| Shield of Faith | `concentration`, 10 мин (100 раундов) |
| Hold Person | `concentration`, 1 мин (10 раундов) |
| урон/лечение (Fire Bolt, Cure Wounds, Fireball, Magic Missile, …) | не указано → `INSTANT` |

## 7. Инварианты

- Часы монотонны (только вперёд) и двигаются ровно в одном месте (`Encounter`).
- Длительность — **данные**, не код; новая длительность = поле в YAML.
- Длительность дополняет событийные триггеры, не заменяет их.
- Backward-compat: все новые поля имеют дефолты (`Spell.duration=INSTANT`,
  `ConditionApplied.expires_at_round=None`, `tracker.clock=None`,
  `TurnContext.clock`/`EncounterDependencies.clock` через `default_factory`).
