# Умирание и спасброски от смерти (этап Q)

Модель «падения до 0 хитов» по Книге Игрока 2024 (стр. 27): спасброски от
смерти, состояние без сознания (dying), стабилизация, мгновенная смерть от
огромного урона и лут трупов.

## Кто использует спасброски

Признак — поле `Creature.uses_death_saves: bool` (по умолчанию `False`).

- **PARTY-существа** (персонажи игроков и важные союзники) — `True`: при 0 HP
  уходят в спасброски, а не умирают мгновенно. Флаг проставляет
  `scenario_builder` для всех существ фракции `PARTY`.
- **NPC/MONSTERS** — `False`: при 0 HP сразу мертвы (`is_alive = False`), на их
  клетке появляется труп (`CORPSE`).

Флаг намеренно **не** привязан к `Faction` (она per-encounter): это свойство
самого существа, поэтому боссу-монстру тоже можно выдать спасброски, выставив
`uses_death_saves = True`.

## Жизненный цикл умирания

1. **Падение в 0 HP.** При смертельном уроне (`DamageResult.was_lethal`)
   `Encounter._on_downed` для PC вызывает `Creature.begin_dying()`:
   - `death_saves = DeathSaveState()` (0 успехов / 0 провалов);
   - накладывается состояние `Unconscious`.
   Инвариант: `death_saves is not None` ⟺ существо в dying (0 HP, ещё не мёртв
   и не поднят).

2. **Спасбросок на старте своего хода.** `Encounter.start_turn` для лежачего PC
   (не stable, не dead) автоматически бросает чистый d20 (без модификаторов):
   - `≥ 10` — успех; **3 успеха** → стабилен (спасброски прекращаются);
   - `< 10` — провал; **3 провала** → смерть;
   - **нат-20** — приходит в сознание с 1 HP (выход из dying);
   - **нат-1** — два провала.
   Публикуется `DeathSaveRolled`; при смерти — `CreatureDied`.

3. **Урон по лежачему.** Обычное попадание → 1 провал, критическое → 2.
   Попадание в упор (≤ 5 фт, melee) по существу с 0 HP — **авто-крит**
   (`AttackAction`), то есть 2 провала.

4. **Огромный урон (massive damage).** Если одиночный удар превысил максимум HP
   (`DamageResult.killed_outright`) — мгновенная смерть, минуя спасброски
   (`death_saves = DeathSaveState(failures=3)`).

5. **Лечение.** Любое восстановление HP > 0 поднимает из dying: `death_saves`
   сбрасывается в `None`, снимается `Unconscious`.

6. **Стабилизация.** `StabilizeAction` (действие, проверка Мудрость(Медицина)
   против Сл. 10) делает умирающего союзника в пределах 5 фт стабильным
   (`DeathSaveState.stabilized()`): спасброски прекращаются, но в сознание он не
   приходит — нужно лечение. Публикует `CreatureStabilized`.

   В одиночной партии стабилизация латентна (нельзя стабилизировать самого себя
   без сознания), но ability `stabilize` зарегистрирован и провязан intent'ом —
   станет рабочей с появлением второго управляемого PC.

## Конец боя при наличии умирающих

Сторона считается **в бою**, пока есть существо, которое либо живо
(`is_alive`), либо «спасаемо» (`uses_death_saves`, в dying, ещё не `is_dead`).
Следствия (`Encounter._is_combatant`):

- лежащий-но-не-мёртвый PC **не** завершает бой — спасброски отыгрываются,
  враги могут добивать;
- PARTY проигрывает, только когда все её спасаемые мертвы;
- если все враги пали, а PC лежит без сознания — победа PARTY (PC остаётся
  dying, в `survivors` не попадает).

## Трупы и лут

При смерти NPC `Encounter._spawn_corpse` кладёт на его клетку
`InteractableObject(kind=CORPSE)` с инвентарём покойного в `state["contents"]`
(canonical-формат `[{"item_id", "qty"}]`). Само мёртвое существо остаётся на
сетке и рисуется как `%` (этап N), труп-объект — контейнер лута.

Лут переиспользует механизм этапа O: `Interact` (открыть, `state["open"]`
становится `True`, но contents **не** очищаются — в отличие от сундука) →
`PickupAction` забирает предметы поштучно через инвентарь-экран. В TUI это те же
хоткеи `i` (открыть) и `l` (лутать).

## События

- `DeathSaveRolled(actor_id, d20_raw, result, successes, failures)` —
  `result ∈ {success, failure, recovered}`.
- `CreatureStabilized(actor_id, by)`.
- `CreatureDied(actor_id)`.

Рендерятся общим `EventPrinter` (CLI + TUI-лог):

```
🎲 hero death save: 14 → success (1/3)
✚ cleric stabilizes hero
💀 goblin died
```

## TUI

Когда у отображаемого PC `death_saves is not None`, `StatusWidget` добавляет
строку пипсов:

```
Hero  HP 0/10  AC 16  Spd 30ft  | Death saves: ●●○ / ○○○
```

(зелёные ● — накопленные успехи, красные ● — провалы; ○ — оставшиеся из трёх).
