# PROGRESSION — баланс, опыт, короткие партии

Документ фиксирует игровой темп: уровни, XP, длительность партии, поощрение
исследования vs боевой стратегии.

Базовая цель: **партия 30–60 минут**, персонаж стартует с **1 уровня**,
финиширует на **3-м**, с одним level-up **прямо во время боя** — это самый
запоминающийся момент в коротких партиях.

---

## 1. Стандартная и быстрая XP-кривые

### 1.1 Стандартная (по книге)

| Уровень | XP суммарно | XP за уровень |
|---|---|---|
| 1 → 2 | 300 | 300 |
| 2 → 3 | 900 | 600 |
| 3 → 4 | 2 700 | 1 800 |
| ... | ... | ... |

Подходит для длинной кампании, **не подходит** для 30-минутной партии.

### 1.2 Быстрая (для MVP)

| Уровень | XP суммарно | XP за уровень |
|---|---|---|
| 1 → 2 | **100** | 100 |
| 2 → 3 | **250** | 150 |
| 3 → 4 | **500** | 250 |
| 4 → 5 | **900** | 400 |

Соотношение между уровнями такое же (~×1.5 разрыв), но числа меньше. Это
позволяет сценарию-демо выдать 1-й level-up через 1–2 встречи и
2-й — на финале.

### 1.3 Реализация — стратегия

```python
class XpCurve(Protocol):
    def threshold(self, level: int) -> int: ...
    def level_for_xp(self, xp: int) -> int: ...

class StandardXpCurve(XpCurve): ...
class FastXpCurve(XpCurve): ...
```

Какая используется — задаётся в YAML сценария:

```yaml
xp_curve: fast        # | standard | milestone
```

`milestone` (alternative) — уровни выдаются по событиям, без счётчика XP.
Может пригодиться для одного-двух сценариев, где важна история, а не подсчёт.

## 2. XP за встречу

### 2.1 Базовая формула

`XP за встречу = сумма CR-значений монстров × 100` (упрощённо для MVP, чтобы
не таскать таблицу CR-XP из книги). Точная таблица CR → XP может быть
подключена позднее как табличный контент.

### 2.2 Распределение в партии

При партии из N PC — XP делится поровну. В MVP N=1, делим на 1.

### 2.3 Бонусы

- **Поиск скрытого** (комната, дверь, предмет): +25 XP за находку.
- **Решение головоломки**: +50 XP.
- **Альтернативный (мирный) путь**: +100 XP, если конфликт обошёлся без боя.
- **Победа в бою с уроном на партию ≤30%**: +25 XP (награда за тактику).

Эти бонусы — **данные** в сценарии (поля `xp_bonus`), а не код.

## 3. Поощрение исследования vs. бой в лоб

Принцип: **обе стратегии валидны**, исследование даёт **относительные**
преимущества, но не обязательно.

| Подход | Получает |
|---|---|
| «иду в лоб» | стандартные XP за бои, стандартный лут. Финишируем сценарий быстрее. |
| «исследую» | XP-бонусы, доп. предметы, **облегчение боя** (например, реликвия даёт +1 к атаке против босса), знание о ловушках, мирный путь. |

### 3.1 Скрытые объекты

В каждой локации может быть `secrets`:

```yaml
secrets:
  - id: false-wall
    type: hidden_passage
    discovery:
      - { passive: 14 }            # пассивная Внимательность
      - { active: { skill: investigation, dc: 12 } }  # действие Изучение
    reveals:
      exit: south
    xp_bonus: 25
  - id: dusty-chest
    type: hidden_object
    discovery: { passive: 16 }
    contains:
      item: talisman-of-fortitude
      coins: { sp: 25 }
    xp_bonus: 25
```

«Пассивная Внимательность» проверяется при входе; «Активная» — когда игрок
делает действие Поиск/Изучение.

### 3.2 Альтернативный путь

В каждой ключевой развилке сценария — два пути. Например, перед финальным
боем:

- **прямой**: дверь, за ней босс с полной силой.
- **обходной**: ход в шахту — требует Атлетику (Сл. 12) или ключ из скрытого
  сундука; даёт возможность напасть на босса со спины (преимущество на первой
  атаке).

Сценарий описывает обе ветки. Игрок волен идти как угодно.

## 4. Level-up в середине боя

Это «вау-эффект» коротких партий. Когда персонаж получает XP, движок
проверяет порог; если пересечён — публикуется событие `LevelUpReady`. UI
показывает игроку: «Вы достигли уровня 2! Прокачаться сейчас?» с тремя
опциями:

- **«Сейчас!»** — открывается визард прокачки (новые особенности, +HP),
  бой ставится на паузу;
- **«После боя»** — отложить до окончания текущего encounter-а;
- **«Подробнее»** — показать, что именно даёт уровень.

Получение HP при level-up в середине боя — **возможность для драматического
спасения**: если PC при 1/18 HP получает +6 HP от уровня — он буквально
«воскресает». Это лучшая фишка коротких партий.

Реализация: бой — конечный автомат; level-up — отдельный sub-state, не
ломающий цикл.

## 5. Шкала сложности боёв

Для MVP — простая шкала:

| Уровень PC | Лёгкий | Средний | Сложный | Босс |
|---|---|---|---|---|
| 1 | 1× CR 1/8 | 2× CR 1/8 | 3× CR 1/8 | 1× CR 1/4 |
| 2 | 1× CR 1/4 | 2× CR 1/4 | 3× CR 1/4 | 1× CR 1/2 |
| 3 | 2× CR 1/4 | 1× CR 1/2 | 2× CR 1/2 | 1× CR 1 |

(CR — Challenge Rating монстра, для MVP делаем 4 ключевых: гоблин CR 1/4,
скелет CR 1/4, гнолл CR 1/2, гоблин-шаман CR 1.)

Сценарий-демо использует эту шкалу.

## 6. Лут и его влияние

«Прокачка снаряжением» — параллельная прогрессии характеристик прокачка.
Тоже стимул исследовать:

| Источник | Что |
|---|---|
| Лёгкий бой | мелочь: 1d6 sp, иногда расходник (зелье лечения 1/3) |
| Средний | 1d4 gp + 1 предмет обычного качества |
| Сложный | 2d6 gp + 1 предмет, шанс 25% — необычное |
| Босс | гарантированный необычный/реликвия по сценарию |
| Скрытый сундук | по сценарию (часто — лучшее) |

Зелья и расходники — короткое, но осязаемое прерывание прогрессии.
В MVP — 3 типа: лечение (2k4+2), щит (+2 КД на бой), сила (+2 STR на бой).

## 7. Балансировка коротких партий — через контент, не правила

Архитектор решил: **играем по чистым правилам книги**. Никаких послаблений
для новичков в коде.

Балансировку коротких партий делаем **только данными сценария**:
- подбор врагов под уровень партии (см. шкалу §5);
- размещение зелий лечения в локациях так, чтобы выживание было
  возможно;
- темп XP — через `xp_curve` сценария.

Никаких флагов `beginner_friendly`, никаких подкручиваний HP и
спасбросков от смерти. Если игрок гибнет — это валидный исход.

## 7a. Реализовано в R1

Этап **R1** реализовал ядро прогрессии (data-driven, расширяемо):

- `Creature` несёт `level`/`xp`/`character_class`/`challenge_rating`/`features`/
  `crit_range_min`/`resource_uses`.
- Классы — данные: `data/content/classes.yaml` + `YamlClassRepository`
  (`ClassProgression`/`ClassLevel`). Воин/Плут L1–3.
- XP-кривые — стратегия (`Fast`/`Standard`/`Milestone`), дефолт `fast`.
- `XpAwardService` начисляет XP за убийство (CR×100) и публикует `LevelUpReady`
  при пересечении порога → level-up **в середине боя** (TUI `LevelUpScreen`:
  «Сейчас / После боя / Подробнее»).
- `LevelUpService` применяет уровень: +HP (фикс. среднее кости + ТЕЛ), prof,
  ячейки, фичи (через `FeatureRegistry`, open/closed).
- **Отдых** — полноценная абстракция `RestService`/`RechargeOn`; в R1 триггерится
  «между боями» (SHORT на старте encounter) — будущие short/long rest вне боя
  зовут ту же службу.
- Фичи R1 (полные по PHB из переиспользующего набора): Improved Critical
  (крит 19–20), Sneak Attack (+Nd6 раз за ход), Second Wind (bonus action heal),
  Action Surge (доп. действие).

## 7b. Реализовано в T1 — Волшебник + профициентные спасброски

Этап **T1** добавил третий класс и довёл механику спасбросков:

- **Волшебник** (`wizard`) — data-driven класс в `classes.yaml`: кость хитов
  `d6`, профициентные спасброски `[INT, WIS]`, ячейки заклинаний по таблице:

  | Уровень | Ячейки 1 круга | Ячейки 2 круга |
  |---------|:--------------:|:--------------:|
  | 1       | 2              | —              |
  | 2       | 3              | —              |
  | 3       | 4              | 2              |

  Фич-список L1–3 пуст (заклинания — через `known_spells`/`spell_slots`, не
  через `FeatureRegistry`); подкласс (Школа магии) на L3 отложен в T4.

- **Профициентные спасброски** — `ClassProgression.saving_throw_proficiencies:
  frozenset[Ability]`, читаются из `classes.yaml` (`saving_throw_proficiencies`)
  и кладутся в `Creature.saving_throw_proficiencies` при сборке из шаблона
  (если передан `class_repository`) и при level-up. Профициентные классы:

  | Класс      | Спасброски с владением |
  |------------|------------------------|
  | Воин       | STR, CON               |
  | Плут       | DEX, INT               |
  | Волшебник  | INT, WIS               |

- **Единая точка спасброска** — `application/engine/saving_throw.py`:
  `saving_throw_bonus(actor, ability)` = модификатор + бонус мастерства (если
  класс профициентен) и `roll_saving_throw(actor, ability, *, dc, ctx, tags)`.
  Все спасброски (урон-заклинания через SAVE-хендлер, проверка концентрации)
  идут через неё — добавить новый источник модификаторов можно в одном месте.

`mage_apprentice` в `mage_skirmish` — PC-волшебник L1 (две ячейки 1 круга);
e2e-смок `tests/e2e/test_wizard_play.py` проверяет сборку и сходимость боя.

## 7c. Реализовано в T4 — подклассы, стили, Cunning Action

Этап **T4** довёл классы до полного L1–3 (выбор — данными шаблона, интерактив
отложен, см. память про интерактивный выбор):

- **Боевой стиль Воина (L1)** — `Creature.fighting_style` из шаблона
  (`fighting_style: defense`), применяется `FightingStyleHandler`; дефолт —
  Defense. Реализованы: **Defense** (+1 КД, пассив), **Archery** (+2 к дальней
  атаке), **Dueling** (+2 к урону рукопашной) — числовые бонусы в helper'е
  `application/engine/features/fighting_styles.py`, `attack.py` их применяет.
  Great Weapon Fighting (переброс 1–2 урона) — отложен (нет reroll-хука).
- **Cunning Action (Плут L2)** — `CunningActionHandler` грантит `cunning_dash`/
  `cunning_disengage` — **Dash/Disengage бонусным действием** (интенты несут
  флаг `bonus_action`; `Dash/DisengageAction` принимают экономику). Hide —
  отложен (стелса нет).
- **Подклассы (L3)** — `Creature.subclass` из шаблона или автодефолт по классу
  (`SubclassHandler`): **Чемпион** (Воин → Improved Critical, крит 19–20),
  **Вор** (Плут → Fast Hands, лёгкая версия; Second-Story Work отложен — нет
  навыков/лазания), **Школа Воплощения** (Волшебник → **Sculpt Spells**:
  союзники кастера не получают урон от его AoE).

Выбор/подкласс/стиль — фичи (хендлеры) + данные (`classes.yaml`) + поля выбора
(domain `Creature`); добавить класс/стиль/подкласс можно без правок движка.

## 8. Что отложено

> Боевые стили, Cunning Action, подклассы L3 (Чемпион/Вор/Школа Воплощения) —
> **реализованы в T4** (см. §7c). Ниже — то, что осталось за рамками.

- **Интерактивный выбор** стиля/подкласса на level-up — T4 фиксирует выбор
  данными шаблона + автодефолт; интерактивный экран выбора отложен до создания
  персонажа (см. память `project_interactive_choice_deferred`).
- **R2** — подсистема навыков/владений + Expertise, Thieves' Cant; полные
  версии Fast Hands (Sleight of Hand) / Second-Story Work (лазание); Great
  Weapon Fighting (reroll урона); Hide/стелс; true short/long rest как
  внебоевые действия (через готовый `RestService`).
- **Arcane Recovery** (Волшебник) — восстановление части ячеек на коротком
  отдыхе; не реализовано, фичи в `classes.yaml` для волшебника нет.
- **Очки характеристик при level-up** — стандартно даются на 4-м, в MVP не
  встретим.
- **Inspiration / Героическое вдохновение** — реализуем интерфейсно, но
  не выдаём в демо-сценарии. Это «бонус» под пост-MVP.
- **Дуэли / арены** — пост-MVP.
