# GLOSSARY — канонические термины проекта

Документ фиксирует единые названия концептов в **коде**, **русскоязычной
документации** и **английских UI-строках**. Цель — устранить
расхождения вида «encounter / бой / битва / стычка» и «square / cell /
клетка / tile», обнаруженные аудитом 01.

При написании кода и текстов используем **только** канонические термины
из таблицы. Другие синонимы — не использовать.

## Особые случаи

### «encounter» vs «бой» vs «встреча»

- **`Encounter`** в коде, **«бой»** или **«стычка»** в RU-документации,
  **«encounter»** или **«fight»** в EN-UI.
- **«Встреча»** допустима только как «случайная встреча» в составе
  `RandomEncounterTable` (или в RU-UI термине «random encounter table» →
  «таблица случайных встреч»).

### «save» vs «snapshot»

Это **разные** понятия — путать нельзя:
- **`Save`** — запись в БД (метаданные `SaveMeta` + BLOB с
  `GameSnapshot`). Создаётся через `SaveRepository.save()`.
- **`Snapshot`** / `GameSnapshot` — объект состояния партии в RAM,
  сериализуемый в JSON. Это то, что **попадает** в BLOB сейва.

### «DM», «GM», «мастер»

- **`Master`** — каноничное имя в коде и текстах.
- **«DM»** допустим только в ссылках на правила книги 5e («см. DM-руководство»).
- **«GM»** не используется.

### «character» vs «creature»

- **`Creature`** — база: любое существо, у которого есть характеристики,
  хиты, КД, состояния.
- **`Character`** — расширение `Creature` для PC: добавляет уровень,
  опыт, мировоззрение, биографию, ячейки заклинаний.
- **`Monster`** — расширение `Creature` для NPC-противника: добавляет
  challenge rating, стратегию AI, лут-таблицу.

NPC мирного типа (например, староста деревни) — это просто `Creature`
с `disposition: friendly`, без `Monster`-надстройки.

## Правила использования

1. В **новых файлах** — используем только канонические термины.
2. В **существующих файлах** — постепенно мигрируем при следующих
   правках; не создаём специально PR «миграция терминологии».
3. В **переводах** (en/ru пары для `LocStr`) — английская строка
   следует EN-UI канону, русская — RU-доке.
4. Если возникает **новый концепт**, не покрытый таблицей — добавляем
   строку сюда в том же PR, в котором появляется концепт.
