# I18N — локализация интерфейса и контента

Архитектор решил:
- **базовый язык UI — английский**;
- **русский** — переключаемая локаль;
- архитектура — по best practices, с адаптацией раскладок под язык.

Документация (`docs/`), чат с разработчиком и комментарии в коде —
**русский**. Это рабочая коммуникация, не пользовательский интерфейс.

---

## 1. Что локализуется и что нет

| Область | Локализация | Где живёт |
|---|---|---|
| UI-строки (меню, кнопки, подсказки, тосты) | да | `src/dnd/i18n/locales/<lang>/ui.po` |
| Лог боя (например, «{actor} hits {target} for {n} damage») | да | то же |
| Имена и описания контента (расы, монстры, заклинания, предметы, локации, диалоги) | да | inline в YAML контента (см. §4) |
| Технические идентификаторы (`goblin`, `attack`, `cure_wounds`) | **нет** | YAML/код |
| Документация в `docs/` | **нет** (русский) | `docs/` |
| Лог технических ошибок и трейсбеки | **нет** (английский) | `logging` |
| Имя локали в настройках | да (отображение) | `i18n/locales/<lang>/settings.po` |

Идентификаторы не локализуем никогда — иначе сейвы развалятся при смене
языка.

## 2. Тулчейн

### 2.1 Базовая технология: `gettext` через `babel`

- **`Babel`** для извлечения, компиляции, форматирования (числа, даты,
  числительные).
- **`.po` / `.mo`** — стандартный формат, поддерживается всем миром,
  редакторы (Poedit) есть везде.
- **Функция `_()` и `ngettext()`** — обёртки. Имена короткие, удобно
  ставить везде.

Альтернативы (Fluent от Mozilla, JSON-словари) — рассматривал; Babel
выигрывает по экосистеме для Python и зрелости.

### 2.2 Пайплайн

```bash
# извлечение ключей в шаблон
make i18n-extract  # → src/dnd/i18n/locales/messages.pot

# обновление переводов (английский — original)
make i18n-update LANG=ru  # мерджит pot в ru/LC_MESSAGES/dnd.po

# компиляция в .mo
make i18n-compile
```

Скрипты в `scripts/i18n/` (когда дойдём).

### 2.3 Загрузка локали

```python
# src/dnd/i18n/translator.py
class Translator:
    def __init__(self, lang: str, base_dir: Path) -> None: ...
    def gettext(self, msgid: str) -> str: ...
    def ngettext(self, sg: str, pl: str, n: int) -> str: ...
    def format(self, msgid: str, /, **vars) -> str: ...

# composition root — единая точка
i18n = Translator(lang=config.lang, base_dir=Path(...))
_ = i18n.gettext
```

`_` подменяется при тестах; в проде — единый глобальный экземпляр после
загрузки конфигурации.

## 3. Дизайн строк: 10 правил, которые экономят боль

1. **Нет конкатенации фраз.** `_("You hit ") + name` — запрещено. Только
   плейсхолдеры: `_("{actor} hits {target}").format(...)`.

2. **Никогда не локализуем имя сущности отдельно от фразы**, если в
   языке требуется падеж/склонение. Русский — флективный язык; «Гоблин»
   и «гоблина» — разные формы. См. §5.

3. **Множественное число — через `ngettext`.** Английский: 1 vs N.
   Русский: 1 / 2-4 / 5+. Babel это умеет.

4. **Числа и даты — через Babel-форматтеры**, не f-string. `format_decimal`,
   `format_datetime`, локаль учтена.

5. **Длина перевода ±50%.** Английская строка → русский переводится в
   среднем длиннее на 20–40%. UI-раскладка не должна ломаться. Если на
   80×24 строка вылезает — перенос или сокращение через ключ-вариант
   (`save_short` / `save_long`).

6. **Контекст для переводчика.** Если ключ неоднозначен —
   `pgettext("button", "Save")` vs `pgettext("rescue", "Save")`.

7. **Никаких маркетинговых каламбуров** в строках UI. Не локализуются.

8. **Ключ — английская строка, не идентификатор.** `_("New game")`, не
   `_("MENU_NEW_GAME")`. Это упрощает чтение кода (видно фразу) и
   совпадает с базовой локалью.

9. **Машинный перевод запрещён.** Лучше дыра в локали, чем «карающее
   зелье» вместо «зелья лечения».

10. **Тестируем оба языка.** Снэпшот-тесты UI выводов идут с
    `lang=en` и `lang=ru`.

## 4. Локализация контента (Q14: вариант C — inline)

YAML контента содержит поля с инлайн-словарём:

```yaml
# content/core/monsters/goblin.yaml
id: goblin
name: { en: "Goblin", ru: "Гоблин" }
description:
  en: "A small green creature with a wicked grin."
  ru: "Мелкий зеленокожий гад с гадкой ухмылкой."
ac: 15
hp: 7
sprite: goblin
ai: skirmisher
```

**Почему inline-словарь, а не bundle:**
- Контент-автор видит локализацию рядом с правилами.
- Не плодит файлы.
- Третий язык — одна строка в каждом поле.

**Если когда-то станет неудобно** (тысячи строк диалога) — миграция в
bundle делается скриптом за вечер.

### 4.1 Псевдоним `LocStr`

```python
class LocStr(BaseModel):
    en: str
    ru: str | None = None

    def resolve(self, lang: str) -> str:
        return getattr(self, lang, None) or self.en
```

`name: LocStr = LocStr.model_validate({"en": "Goblin", "ru": "Гоблин"})`.

`pydantic` это съест и провалидирует. Если перевод отсутствует — фоллбэк
к `en` (никогда не ломается).

### 4.2 Скрипт-валидатор

`dnd content validate` проверяет:
- наличие хотя бы `en` в каждом локализуемом поле;
- покрытие активной локали (если не 100% — warning);
- отсутствие неиспользуемых ключей в `.po`.

## 5. Падежи и согласование (русский)

Английский легко. Русский — сложно. План:

**Уровень 1 (MVP):** избегаем падежей в шаблонах. Вместо:

> `_("You hit {target} for {n} damage")`
> → ру: «Вы ударили {target} на {n} урона» — здесь {target} в винительном.

Делаем:

> `_("Hit! {target} takes {n} damage")`
> → ру: «Попадание! {target} получает {n} урона» — здесь {target} в
> именительном, склонять не надо.

Этого почти всегда хватает. Если совсем никак — выходим на §уровень 2.

**Уровень 2 (потом):** дополнительные формы у `LocStr`:

```yaml
name:
  en: "Goblin"
  ru: "Гоблин"
  ru_acc: "Гоблина"   # винительный
  ru_dat: "Гоблину"   # дательный
```

В шаблонах — `{target:acc}` (Babel custom format). Это уже backstage.

В MVP — **только именительный**.

## 6. Структура каталогов

```
src/dnd/i18n/
├── __init__.py
├── translator.py
└── locales/
    ├── messages.pot                 # шаблон ключей UI
    ├── en/LC_MESSAGES/dnd.po        # английский (== source)
    └── ru/LC_MESSAGES/dnd.po        # русский

content/core/.../*.yaml             # инлайн ru/en поля
```

`.mo` (бинарные) собираем при установке/release-сборке.

## 7. UI и адаптация раскладки

Раскладки (`docs/UI.md` §2.2) рассчитаны на минимальный размер 80×24.
Русский длиннее → проверяем на этапе локализации:

- При запуске UI делает «sanity-check»: пересчитывает ширину ключевых
  меток для текущей локали и подбирает preset.
- Если ярлык не помещается — берёт «короткий вариант» (`*_short` ключ).

Пример:

```
_("New game")          → ENG: "New game"   |  RU: "Новая игра"
_("New game_short")    → ENG: "New"        |  RU: "Новая"
```

Короткие версии используются только в узких раскладках; в `messages.pot`
автоматически предлагаются.

## 8. Шрифты, кодировка, терминалы

- Источник — UTF-8 повсюду.
- Терминал — UTF-8. На Windows ставим `chcp 65001` при старте (через
  `os.system` в `compose_root`).
- Кириллица в моноширинных шрифтах: проверяем на стандартных
  (DejaVu Sans Mono, JetBrains Mono, Cascadia Code, Consolas). В TUI
  работает через Textual + rich.

---

## 9. Конфиг

```toml
# ~/.config/dnd/config.toml
[i18n]
lang = "en"          # "en" | "ru"
fallback = "en"
date_format = "iso"
```

Команда `dnd settings lang ru` меняет в сейве и в конфиге.

## 10. Что отложено

- Дополнительные языки (es, zh, ...) — добавятся новой папкой в `locales/`,
  кода менять не нужно.
- Падежи (уровень 2 §5) — пишем UI так, чтобы пока обходиться без них.
- Локализация имени сценария «Шахта Гнилого Дуба» — да, на английский
  переведём: `Hollow Oak Mine`. Контент сценария — bilingual.
