# Этап S — Меню способностей (выбор + перебинд хоткеев)

> TUI-надстройка над готовой системой `Ability`/`AbilityRegistry`/`build_keymap`.
> Движок не трогаем. Предусловие для волшебника (много заклинаний — выбор
> списком, а не по одному хоткею).

## 1. Проблема

Способности сейчас вызываются только по жёстким default-хоткеям (`BINDINGS` +
per-creature `keybindings` + заклинания на цифрах 1–9). Нет UI:
- **выбрать** способность из списка (нужно, когда их больше, чем удобно помнить
  по хоткеям — особенно у волшебника 8+ заклинаний);
- **переназначить** хоткей под себя в бою.

Фундамент готов: `Ability` (dataclass с `id/icon/default_hotkey/economy_cost/
requires_target/requires_path/intent_factory`), `AbilityRegistry`,
`Creature.ability_ids`, `Creature.keybindings` (override key→ability_id),
`build_keymap(actor, registry)`, `ActionBarWidget`, mode-машина BattleScreen
(NORMAL/MOVE/TARGET) и паттерн модалок (`LevelUpScreen`).

## 2. Решение

### 2.1 `AbilityMenuScreen(ModalScreen)`
Модальный список способностей активного PC. Открывается клавишей **`Tab`** в
NORMAL-режиме (в NORMAL Tab свободен; в TARGET/MOVE он уже занят циклом/шагами —
там меню не открываем).

Источник строк — **единый**: `actor.ability_ids → AbilityRegistry.get(aid)`.
Никакого параллельного хранилища. Заклинания, зарегистрированные как `Ability`
(см. §2.4), попадают сюда автоматически.

Каждая строка:
```
[<hotkey>] <icon> <Имя>            <статус>
```
- `<hotkey>` — текущая привязка из `build_keymap` (или `—`, если не на клавише);
- `<статус>` — «доступно» либо причина недоступности (нет действия/бонуса,
  нет ресурса/слота). Недоступные — приглушённым стилем, применить нельзя.

Навигация: `↑`/`↓` — выбор, `Enter` — **применить**, `b` — **перебинд**,
`Esc` — закрыть. (Хелп-строка снизу.)

### 2.2 Применение
`Enter` на доступной строке: закрыть меню и вызвать `ability.intent_factory(...)`,
далее — существующая mode-машина BattleScreen:
- `requires_target` → TARGET-режим (Tab-цикл целей);
- `requires_path` → MOVE-режим;
- иначе (self/стойка) → сразу `PlayerIntent` в очередь.
Меню — просто **ещё одна точка входа** в уже существующие пути; новой боевой
логики нет.

### 2.3 Перебинд (на сессию)
`b` на выбранной строке → подсказка «нажмите клавишу» → следующая нажатая
буквенно-цифровая клавиша пишется в `actor.keybindings[key] = ability.id`.
Хелпер `rebind_ability(actor, key, ability_id, registry)`:
- снимает прежнюю привязку этой клавиши (если была) — одна клавиша = одна
  способность;
- снимает прежнюю клавишу этой способности из `keybindings` (чтобы способность
  не висела на двух клавишах);
- пишет новый бинд; keymap пересобирается через `build_keymap`.
Только в памяти (`Creature.keybindings`). Персист на диск — **отложено** (когда
будет settings/загрузка; бинды привяжем к персонажу — см. note в плане).
`Esc` во время «нажмите клавишу» — отмена.

### 2.4 Готовность к волшебнику (ключевое, но реализуется на этапе мага)
Принцип: **всё — `Ability`**. Заклинания регистрируются как `Ability`
(`icon` + `intent_factory=lambda target_id: CastSpellIntent(spell_id=…, …)`),
кладутся в `ability_ids` → автоматически в меню. Это снимает блокер «много
заклинаний». В этапе S мы НЕ добавляем мага, но проверяем меню на акторе с
кастер-способностями (можно временно — Apprentice Mage уже имеет spell-ability'и
в action-bar).

**AoE-стык:** у `Ability` сейчас только `requires_target/requires_path`.
Для зон (origin/area) на этапе мага добавим `requires_area` → существующий
`BattleMode.AREA`. В S — вне области; AoE-заклинание из меню пока показываем,
но его триггер из меню сведём к точечному пути или пометим «через хоткей».
(Уточнить при реализации мага.)

## 3. Расширяемость / инварианты
- Меню читает реестр — новые способности появляются в нём без правок UI.
- Default-хоткеи и action-bar остаются как есть (меню — дополнение, не замена;
  всё текущее интеграционное покрытие не ломается).
- `requires_target ∧ requires_path` уже запрещены в `Ability.__post_init__`.
- Перебинд не должен ломать инвариант «default-хоткеи не коллизятся» — коллизию
  гасим снятием старого бинда.

## 4. Тестирование
- **Юнит** `rebind_ability`: назначение, снятие старой клавиши, снятие старой
  привязки способности, коллизии.
- **Юнит** «доступность строки»: способность без ресурса/экономии → недоступна.
- **Pilot-смоук**: `Tab` открывает меню → список с хоткеями/статусами; `Enter`
  на Attack → BattleScreen в TARGET-режиме; перебинд Attack на `z` → keymap
  обновлён (`z`→attack, старый хоткей снят).

## 5. Вне scope
- Сам класс «Волшебник» и заклинания L1–L3 — следующий этап.
- Персист биндов на диск (отложено к settings/загрузке; привязка к персонажу).
- `requires_area`/AoE из меню — стык к этапу мага.
- CLI (не-TUI) меню способностей — TUI-first; CLI остаётся как есть.
