# UI — пользовательский интерфейс, ASCII, темы, локализация, hot-seat

Документ фиксирует, как игра выглядит, как масштабируется, как
рендерится боевая карта, как переключаются язык и тема, как ведёт себя
hot-seat-режим (заложен на будущее), как охраняется приватная панель
мастера.

База языка интерфейса — **английский**, переключаемая локаль —
**русский**. См. `I18N.md`.

---

## 1. Два уровня интерфейса

| Уровень | Технология | Назначение |
|---|---|---|
| **CLI** | Typer + questionary + rich | Скриптуемый, диалог «вопрос-ответ», без фуллскрина. Удобен для тестов, отладки, прохождения без эстетики. |
| **TUI** | Textual | Полноэкранный режим: рамки, панели, темы, ASCII-карта боя, спрайты. По умолчанию. |

Оба — адаптеры одного и того же порта `UserInterface`. Игра не знает,
какой UI активен. `dnd play` → TUI; `dnd play --no-tui` → CLI.

## 2. Размеры терминала и масштабирование

### 2.1 Целевые размеры

| Размер | Кол-во ячеек | Кому |
|---|---|---|
| **Минимум** | 80×24 | универсальный (esc-fallback) |
| **Стандарт** | 120×40 | большинство современных терминалов |
| **Расширенный** | 160×50+ | широкоэкранный |

При запуске TUI измеряет реальный размер (`textual.app.size`) и
выбирает **раскладку** (layout preset). Меньше 80×24 — отказ TUI с
подсказкой «увеличьте окно или используйте `--no-tui`».

### 2.2 Раскладки

Все экраны делятся на «панели». Раскладка решает, какие панели есть и
где.

**80×24 (minimum):**

```
┌─ STATUS ───────────────────────────────────────────────────────────────────┐
│ Aelar, Fighter 2  HP 14/18  AC 16  Init 12  XP 240/300                     │
├─ VIEW ───────────────────────────────────────┬─ LOG ────────────────────────┤
│  battle map 50×20 or location text           │  > Aelar attacks            │
│                                              │  > hit, 8 damage            │
│                                              │  > goblin wounded           │
│                                              │  > ...                       │
├─ ACTIONS ────────────────────────────────────┴──────────────────────────────┤
│ [A] attack  [M] move  [D] dodge  [I] inventory  [?] help                   │
└────────────────────────────────────────────────────────────────────────────┘
```

**120×40 (standard) — добавляем «легенду» и «инициативу» сбоку:**

```
┌─ STATUS ───────────────────────────────────────────────────────────┬─ PARTY ───────────────┐
│ ...                                                                │ Aelar    HP 14/18     │
│                                                                    │                       │
├─ VIEW (battle map ~85×26 cells) ───────────────────────────────────┤                       │
│                                                                    ├─ INITIATIVE ──────────┤
│                                                                    │ 1▶ Aelar    12        │
│                                                                    │ 2  Goblin1  10        │
│                                                                    │ 3  Goblin2   8        │
│                                                                    ├─ LEGEND ──────────────┤
│                                                                    │ @ — Aelar             │
│                                                                    │ g — goblin            │
│                                                                    │ # — wall              │
├─ LOG ──────────────────────────────────────────────────────────────┴─ ACTIONS ─────────────┤
│ ...                                                                                         │
└─────────────────────────────────────────────────────────────────────────────────────────────┘
```

**160×50+ — больше спрайты, инвентарь сбоку постоянно:**

```
┌─ STATUS ─┬─ PARTY ──┬─ VIEW (battle map ~110×36, sprites 5×3) ──┬─ INITIATIVE ──┬─ LEGEND ─┐
│ ...      │ Aelar    │                                           │ ...           │ ...      │
│          │ ...      │                                           │               │          │
├──────────┴──────────┤                                           ├───────────────┴──────────┤
│ INVENTORY           │                                           │ ACTIONS                  │
│ • long sword        │                                           │ ...                      │
│ • bow               │                                           │                          │
└─────────────────────┴───────────────────────────────────────────┴──────────────────────────┘
```

### 2.3 Реалтайм-смена размера

Textual нативно поддерживает `on_resize` — пересчитываем раскладку. Игра
не прерывается; UI выбирает другой preset. При значительном уменьшении
ниже минимума — пауза и подсказка.

### 2.4 Локализация раскладки

Русский длиннее английского на ~20–40% (см. `I18N.md` §3). При выборе
preset UI проверяет ширину ключевых меток для активной локали и:
- если умещается — используется полная форма;
- если нет — короткая форма (`*_short` ключ в `.po`).

## 3. Темы

**Две темы**, по решению архитектора:

### 3.1 `color` (по умолчанию)

Современная, «красивая ретро»-палитра. Тёмный фон, акценты по семантике:

| Сущность | Цвет |
|---|---|
| Player character | yellow / bright |
| Friendly NPC | cyan |
| Neutral NPC | yellow |
| Enemy | red |
| Dead/unconscious | dark grey |
| Object/chest | blue |
| Magical effect | magenta |
| Walls | white dim |
| Difficult terrain | brown / dim yellow |

Заголовки рамок — чуть ярче основного текста. Текст лога — нейтральный
white, **подсветка** имён существ согласно их семантике.

### 3.2 `monochrome`

Чёрно-белая. Семантика передаётся **яркостью и выделением** (bold/dim/
inverse), а не цветом. Для скриншотов, старых терминалов, людей с
цветоблиндом по умолчанию без настроек.

### 3.3 Реализация

Темы — CSS-файлы Textual:

```
src/dnd/interfaces/tui/themes/
  color.tcss
  monochrome.tcss
```

Никакого хардкода цветов в виджетах. Цвета через CSS-переменные:
`$pc-fg`, `$enemy-fg`, `$wall-fg` и т.п. — обе темы переопределяют.

Переключение — настройкой `theme = "color" | "monochrome"`, hot-reload
без перезапуска (Textual поддерживает).

## 4. ASCII-спрайт-система

### 4.1 Структура спрайта

YAML-файл в `content/sprites/`:

```yaml
id: goblin
char_small: g                # 1×1 для минимальной карты
sprite_medium: |             # 3×3 для стандартной
   ,_,
   o^o
   /|\
sprite_large: |              # 5×3 / 5×5 для широкого
   .-.-.
  ( o o )
   '-v-'
char_dead: x                 # 1×1 — что показать, когда мёртв
sprite_color_token: enemy    # семантика: pc | friendly | neutral | enemy | object
description:
  en: "Small green humanoid, mean and quick."
  ru: "Мелкий зеленокожий, злой и шустрый."
```

`sprite_color_token` — какой CSS-цвет применить в теме. В `monochrome`
все токены сводятся к bold/dim.

### 4.2 Выбор формы

| Размер клетки в ячейках | Спрайт |
|---|---|
| ≤1×1 | `char_small` |
| 3×3 | `sprite_medium` |
| ≥5×3 | `sprite_large` |

Размер клетки выбирает движок UI исходя из preset и размера карты.

### 4.3 Несколько существ на клетке

См. `ENGINE.md` §2.2.

- **small-зум:** показываем основной символ + индекс «²/³» снизу;
  если ≥4 — `+`.
- **medium/large-зум:** рисуем доминирующий по приоритету
  (PC > friendly > enemy > object > terrain), в углу значок «²».
- В легенде боя — раскладка «square (3,5): @Aelar +Skeleton1 +Skeleton2».
- При наведении курсора на клетку с несколькими — `Tab` циклически
  переключает фокус.

## 5. Карта боя в ASCII (квадраты)

### 5.1 Развёртка

Каждая клетка — прямоугольник из ячеек терминала. На small-зум — 1×1
ячейка, на medium — 3×3, на large — 5×3.

**small (1×1):**

```
##########
#........#
#...,,...#
#...,,...#
#..g.....#
#........#
#...@....#
##########
```

**medium (3×3):**

```
┌───┬───┬───┬───┐
│   │   │   │   │
│   │   │ g │   │
│   │   │   │   │
├───┼───┼───┼───┤
│   │ @ │   │   │
│   │   │   │   │
│   │   │   │   │
└───┴───┴───┴───┘
```

Линии — единые на всю карту (рамки общие), это экономит ячейки.

### 5.2 Слои рендера

1. **Terrain** (`.`, `,`, `#`, `^`, `~`).
2. **Objects** (двери, сундуки, ловушки если видны).
3. **Creatures** (`@`, `g`, `o`, ...).
4. **Effects** (область заклинания — фон клетки тонируется).
5. **Cursor** (мигающий маркер цели/выбора).
6. **Movement preview** (стрелки/точки пути при предпросмотре движения).

### 5.3 Подсветка инициативы

- Очередь — отдельная панель `INITIATIVE`. Текущий ход помечен `▶`.
- На карте текущий ходящий обведён яркой рамкой клетки.
- Следующий — пунктирной рамкой.

### 5.4 Управление в бою

- **Arrows / hjkl** — двигать курсор.
- **Shift+Arrows / yubn** — диагонали.
- **Enter** — выбрать клетку как цель.
- **A** — меню атаки (подсвечивает достижимые клетки).
- **M** — режим движения (подсвечивает доступный диапазон).
- **F** — фокус: статблок существа под курсором в боковой панели.
- **Tab** — циклически между существами в одной клетке/видимыми.
- **Esc** — отмена / назад.
- **S** — открыть статистику бросков.
- **?** — помощь по клавишам (всегда доступна).

## 7. Статистика бросков

См. `ENGINE.md` §7 (источник данных).

### 7.1 Что показываем

Источник — `RollIssued`-события, фильтр: `dice == d20`, поле `raw`
(до бонусов и преимущества).

- **Session avg:** среднее сырого d20 в текущей сессии.
- **Save avg:** среднее за всё время в этом сейве.
- **Luck delta:** `session_avg − 10.5` (теоретическое матожидание).
  Положительный — везёт, отрицательный — не везёт.
- **Distribution:** мини-гистограмма по 20 граням (1..20), высота
  столбцов нормирована к высоте панели.

### 7.2 Где показываем

- **Лист персонажа → вкладка Journal** — полная статистика +
  гистограмма.
- **В бою — мини-индикатор в правом углу:** одно число «luck delta»
  + цветовой акцент (зелёный/жёлтый/красный).
- **Быстрый просмотр клавишей `S`** — оверлей.

### 7.3 Что фиксируем

| Поле | Описание |
|---|---|
| roll_id | UUID |
| t | timestamp |
| dice | `d20` / `d6` / ... |
| count | количество кубов |
| raw | tuple сырых значений |
| modifier | сумма бонусов |
| total | итог после модификаторов и преимущества |
| advantage / disadvantage / crit | флаги |
| context_kind | `attack` / `damage` / `save` / `ability_check` / `initiative` |
| actor | id существа |

В отчёт идёт **только d20** и **только raw**. Это и было решением
архитектора — честное матожидание удачи.

## 8. Hot-seat (заложенные инварианты, не реализация)

Сейчас один игрок. Чтобы потом hot-seat подключился:

- В UI-стейте есть `active_controller_id`. Сейчас один.
- Между ходами PC (когда `active_controller_id` меняется) — экран
  **передачи управления**:

```
        ┌─────────────────────────────────────┐
        │                                     │
        │      Pass control to {next_player}  │
        │                                     │
        │           [ press ENTER ]           │
        │                                     │
        └─────────────────────────────────────┘
```

- Поведение настраивается: `handover_mode: auto | confirm` (см. Q18). По
  умолчанию `confirm`.

- Между ходами разрешено:
  - смотреть **только** лист своего активного PC (на small/medium
    layout — только он отображается);
  - на больших layout (120+) — список членов партии видимостью
    «только имя и HP», без раскрытых статов других PC.
- Действия за чужого PC — запрещены. UI блокирует.

- Когда добавим мастера — `MasterScreen` входит **поверх** через PIN.

## 9. Приватная панель мастера (направление развития)

В hot-seat мастер и игроки сидят за одним устройством. Защита панели —
PIN-код.

- При создании партии — мастер задаёт PIN (если он есть в роли).
- PIN хранится в сейве как `sha256(pin + salt)`.
- Вход в `MasterScreen` — клавишей `Ctrl+M`, диалог ввода PIN.
- Неверный PIN — короткий «зум» (мигание) и возврат в обычный UI.
- При выходе из `MasterScreen` — клик «return to players» очищает
  экран на 1 сек (защита от подсматривания).

В MVP вход в `MasterScreen` отключён (роли MASTER нет). UI код
готов на сейчас — экран будет добавлен потом.

## 10. Интерфейс «UI ↔ движок»

UI слушает события из `EventBus` и подписывается на запросы от движка
через `UserInterface`. Никогда не вызывает domain напрямую.

**Канонический контракт `UserInterface`** — в
[`ARCHITECTURE.md` §3.3](ARCHITECTURE.md). Здесь — UI-специфичные
особенности и заметки.

Ключевые правила, которым обязан подчиняться **любой** адаптер
(`TextualUserInterface`, `CliUserInterface`, тестовый `RecordingUI`):

1. **Все строки подаются по ключам i18n**, не готовыми текстами. Поля
   запросов называются `prompt_key`, `description_key` и т.п. — никаких
   `prompt: str`. См. `I18N.md` §3 правило 1.
2. **`AnyView`** — union DTO представления (`BattleView`,
   `ExplorationView`, `CharacterSheetView`, `InventoryView`, ...). UI
   знает, как нарисовать каждый. `EngineStateView` оборачивает их
   вместе с режимом движка.
3. **Никакой бизнес-логики в UI.** Адаптеры — только рисуют и собирают
   ввод. Любые проверки правил — на стороне движка.
4. **i18n через порт `Translator`**, не глобальный `_`. Адаптер
   получает Translator при создании.
5. **TUI обязан корректно отрабатывать `on_resize`** и пересобирать
   раскладку без потери состояния.

Если в будущем понадобится — `UserInterface` будет разбит на узкие
`InputPort` / `OutputPort` (см. `OPEN_QUESTIONS.md` Q21). На MVP —
один порт.

## 11. Доступность и совместимость

- Никаких эмодзи. Только псевдографика IBM437 / базовый Unicode
  (`═║╔╗╚╝`, `░▒▓█`).
- Запасной режим `--ascii-only` рисует всё буквами и `+-|` (для очень
  старых терминалов).
- В `monochrome`-теме все цветовые подсказки сведены к bold/dim/inverse.
- UTF-8 повсюду, на Windows ставим `chcp 65001`.

## 12. Что отложено

- Темы phosphor-green / amber / vga-16 — добавятся как `.tcss`-файлы
  без правок кода, если архитектор пожелает.
- Мышь — клавиатура достаточно; Textual поддерживает мышь — включим
  опционально.
- Скриншот в PNG — нет.
- Live-master UI — описан в `MASTER.md`, реализация пост-MVP.
- LiveDiceRoller (ввод значения с настоящих кубиков) — пост-MVP.
